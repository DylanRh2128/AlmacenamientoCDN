# Testing

Run with: `pytest` (needs `DATABASE_URL`, `API_KEY`, and the AWS/CloudFront variables set to any
dummy value — tests never call real AWS).

- `tests/test_file_validation.py` — valid JPEG/PNG/PDF pass; an unsupported content type is
  rejected; a spoofed content type (right header, wrong magic bytes) is rejected; an oversized
  file is rejected.
- `tests/test_cloudfront_signer.py` — signs a URL with a throwaway in-memory RSA key pair
  (generated by the test itself, never a real AWS/CloudFront key) and checks the resulting URL
  carries `Key-Pair-Id`, `Signature`, and a future `Expires` timestamp.
- `tests/test_files_api.py` — `POST /files` happy path and invalid content type; missing
  `X-API-Key` → `401`; `GET /files`; `GET /files/{id}/download-url` including `404`;
  `DELETE /files/{id}` including `404`, and that S3 deletion is actually called.
  `app.files.upload_file`, `delete_file`, and `generate_download_url` are all monkey-patched
  (see `tests/conftest.py`) so tests never touch S3 or CloudFront.
